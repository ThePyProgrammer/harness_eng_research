# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Astro/Starlight built-ins only for Phase 1 foundation; no custom reader-facing shell yet |
| Icon library | Starlight/default Astro icon support only; no separate icon package required in Phase 1 |
| Font | System stack: `ui-serif, Georgia, Cambria, "Times New Roman", Times, serif` for prose headings; `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` for labels/navigation; `ui-monospace, "SFMono-Regular", Consolas, "Liberation Mono", monospace` for paths and diagnostics |

**Source and scope:** CONTEXT.md D-05/D-07 select Astro/Starlight as the default baseline and limit theme work to foundations. Codebase scouting found no existing `components.json`, Tailwind config, web package, or reusable UI component system at the repository root. Because the selected phase stack is Astro/Starlight rather than React/Next/Vite, shadcn initialization is not part of this phase contract.

**Phase-1 UI boundary:** The visible surface is a foundation/provenance layer only: a minimal static homepage or docs landing page, corpus inventory page, provenance/source status treatment, and validation diagnostics documentation. Do not implement the full book reading shell, chapter prose layout, search UX, graph exploration, or formal object registry in Phase 1.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline metadata separators, compact status badges |
| sm | 8px | Compact element spacing, badge padding, path/status row gaps |
| md | 16px | Default element spacing, form/control gaps, list item padding |
| lg | 24px | Section padding, inventory card padding, validation message spacing |
| xl | 32px | Layout gaps between inventory groups and documentation sections |
| 2xl | 48px | Major section breaks on landing/inventory pages |
| 3xl | 64px | Page-level top/bottom spacing on desktop |

Exceptions: Interactive controls and links rendered as buttons must have a minimum hit target of 44px height or width. Inline source-path links inside dense metadata tables may keep text-sized line boxes, but must retain visible focus outlines and at least 8px vertical row padding.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.15 |

**Type contract:** Use exactly these four sizes in Phase 1 UI. Use only two weights: 400 and 600. Source paths, command names, and validation codes use the monospace family at the Body or Label size; do not introduce extra small diagnostic text below 14px.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F3EA` | Page background, main reading surface, documentation canvas |
| Secondary (30%) | `#E8DDC8` | Inventory cards, provenance panels, sidebar/nav surfaces, table headers |
| Accent (10%) | `#7A3E1D` | Primary CTA, active navigation state, canonical-source status badge, focused source-path links |
| Destructive | `#B42318` | Missing source, invalid archive-as-canonical status, validation failure summaries only |

Accent reserved for: primary CTA (`Inspect Corpus Inventory`), active navigation marker, canonical/source-valid status badges, focused source-path links, and one highlighted provenance rule callout per page. Do not use accent for every link or every interactive element.

**Secondary semantic status colors:** Use `#475569` for neutral/provenance-only status text and `#166534` only for pass/success validation summaries. Destructive red is reserved for hard validation failures and archive misuse diagnostics.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Inspect Corpus Inventory |
| Empty state heading | No corpus entries found |
| Empty state body | Add the umbrella framework and all twelve pillar entries to the typed inventory before running the static build. |
| Error state | A required canonical source path is missing or points into an archive. Fix the inventory entry so it references `science/paper/` or `pillars/*/paper/`, or mark the entry explicitly as provenance-only content. |
| Destructive confirmation | Not applicable: Phase 1 UI must not expose destructive reader-facing or corpus-mutating actions. Validation failures block builds; they do not delete or rewrite files. |

**Validation diagnostic copy pattern:** Use `Entry {id}: {field} points to {path}. {reason}. {next step}.` Example: `Entry security: canonicalTex points to pillars/security/archive/security_architecture.tex. Archive paths cannot be canonical sources. Move the reference to pillars/security/paper/ or mark the entry as provenance-only.`

**Status labels:** Use exactly `Canonical`, `Missing source`, `Archive blocked`, and `Provenance-only` for inventory/source status badges.

## Interaction Contract

| Surface | Required behavior |
|---------|-------------------|
| Landing/foundation page | Present the static-site boundary, one build command, one validation command, and the primary CTA `Inspect Corpus Inventory`. |
| Corpus inventory page | Show exactly thirteen expected entries: umbrella framework plus twelve pillars. Each row/card must expose title, kind, slug, source status, canonical `.tex` path, PDF path, and bibliography path when present. |
| Source-path links | Render paths as monospace text. Links to canonical sources open as normal same-site/static links when available; broken paths must be visually marked through validation output, not silently hidden. |
| Validation documentation | Show pass/fail examples for missing canonical paths and archive-as-canonical paths. Failure examples use Destructive color and include the next fix step. |
| Keyboard behavior | All navigation links, CTA controls, and source-path links must be keyboard reachable in document order with a visible 2px outline in Accent color and 2px offset. |
| Responsive behavior | At widths below 720px, inventory metadata stacks vertically; source paths wrap with `overflow-wrap: anywhere`; no horizontal page scrolling except inside explicit code blocks. |

---

## Accessibility Contract

- Use semantic headings in a single ordered hierarchy: one `h1` per page, then `h2` for major sections and `h3` for inventory groups or diagnostic examples.
- Maintain accessible contrast: body text and labels at 4.5:1 minimum; large display text at 3:1 minimum; focus indicators at 3:1 minimum against adjacent colors.
- Do not communicate provenance status by color alone. Every status badge must include text from the status label set.
- Validation failure examples must be readable without terminal color support and must include the affected entry id and path in text.
- Keep the Phase 1 pages fully static; no account state, server runtime, hosted search UI, analytics prompt, or network-dependent interaction.
