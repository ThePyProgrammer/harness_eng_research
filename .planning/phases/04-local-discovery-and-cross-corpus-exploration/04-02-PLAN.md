<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Relation metadata -> chapter HTML | Curated relation records become public navigation and source/provenance claims. |
| Relation metadata -> formal-object HTML | Curated object-scoped relation records become public navigation beside stable IDs, source tiers, and formal anchors. |
| Validation CLI -> build pipeline | Invalid discovery metadata must stop static generation before misleading links ship. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering | `site/src/data/relations.ts` | mitigate | Zod schema plus `validateDiscovery()` checks type IDs, source IDs, target IDs, directionality, family constraints, duplicate IDs, and labels. |
| T-04-05 | Repudiation | Source/provenance related links | mitigate | Keep SourceLinkPanel/source trails visible and validate source/provenance relation target families; do not allow archive paths to masquerade as canonical sources. |
| T-04-06 | Spoofing | User-facing relation labels | mitigate | Relation labels must come from registered relation type records, not arbitrary raw strings in relation rows. |
| T-04-07 | Information Disclosure | Formal-object related-link rows | mitigate | Render only curated relation labels, target titles/families, rationales, and direct public anchors; do not expose internal raw IDs as the primary user-facing label when readable labels exist. |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan; if executor attempts one, stop and require package legitimacy review. |
</threat_model>
