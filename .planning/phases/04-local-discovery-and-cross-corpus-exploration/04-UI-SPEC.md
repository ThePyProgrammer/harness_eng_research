## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline metadata gaps, compact edge-label spacing |
| sm | 8px | Search result metadata gaps, chip padding, compact route-stop internals |
| md | 16px | Default element spacing, card internals, related-link row gaps |
| lg | 24px | Section padding, route-map stop padding, graph neighborhood panel padding |
| xl | 32px | Layout gaps between search groups, route branches, related-link sections |
| 2xl | 48px | Major section breaks between search, paths, relation, and graph surfaces |
| 3xl | 64px | Page-level top/bottom spacing for discovery landing, reading path pages, and graph overview |

Exceptions: interactive targets must keep the established `min-height: 44px` for links, buttons, chips, search filters, route-map stops, graph nodes, and related-link targets. Static SVG connector strokes may use sub-4px stroke widths because they are decorative/non-interactive; clickable SVG or HTML graph nodes still require a 44px target.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.15 |

Typography contract:

- Use exactly these four size roles for Phase 4 UI text; do not add intermediate sizes for graph labels or search metadata.
- Use exactly two weights: 400 for prose/snippets/rationales and 600 for headings, labels, relation chips, result type labels, and CTA text.
- Search snippets, route-stop explanations, relation rationales, and graph node descriptions use Body/400/1.5.
- Result group names, relation type labels, path branch labels, graph category labels, and metadata keys use Label/600/1.4 with uppercase only where the existing atlas/formal style already uses eyebrow labels.
- Reading path titles, search page title, and graph overview page title use Display/600/1.15.
- Branch headings, result titles, route-stop titles, and related-link section headings use Heading/600/1.2.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F3EA` | Page background, route-map canvas background, graph overview background, empty-state background, search page shell |
| Secondary (30%) | `#E8DDC8` | Cards, sidebars, search result groups, related-link panels, route-stop cards, graph neighborhood panels, nav surfaces |
| Accent (10%) | `#7A3E1D` | Primary CTA, focused borders, active route branch, typed relation chips, anchor links, graph connector strokes, current/selected search filter |
| Destructive | `#B42318` | Invalid metadata warnings, failed search/index validation UI, archive-blocked/provenance error treatment only |

Accent reserved for: primary CTA links, visible focus outlines, active/selected search filters, active route branch markers, relation type labels/chips, anchor/deep-link affordances, graph connector strokes, graph node borders on hover/focus, and current-path indicators. Do not use accent as a generic fill for every card or paragraph.

Additional existing semantic colors may be preserved only where already established: `#166534` for canonical/success/source-valid states and `#475569` for muted/provenance metadata. Do not invent new category colors for every relation type; relation taxonomy should be readable by labels first and color second.

## Phase 4 Interaction Contracts

### Reading Paths

- Render the five required paths as branching route maps, not essays and not flat indexes: building a harness, scaling multi-agent work, cost/latency, production hardening, and AI code degradation.
- Each path page must present: path title, one-sentence purpose, branch list/map, route stops, and direct links to chapters, concepts, formal objects, citations, or anchors.
- Each route stop must expose by default: stop title, target type, `Why this stop matters`, and one direct link labeled `Open stop`.
- Branching must remain legible on narrow screens by collapsing to a vertical ordered/list route while preserving branch labels and target links.
- Route-map connectors are decorative unless implemented as links; if decorative, mark SVG connector layers `aria-hidden="true"` and keep the semantic order in HTML.
- Reading paths complement the existing book spine and footer navigation; they must not replace `BookFooterNav` or source trails.

### Local Search

- Search must be local/static with no hosted service and no runtime server dependency.
- Search UI must group results by type: Pages, Formal Objects, Concepts, Citations, Reading Paths.
- Search must expose type context before click. Formal-object hits must show object kind, stable ID/title, owner chapter/pillar, matched snippet, and direct anchor link.
- Search result links must deep-link to stable anchors where a formal object or citation anchor exists; page-top links are acceptable only for page-level results.
- Search filters, if present, must be buttons or checkbox controls with visible selected state, keyboard focus, and 44px minimum target height.
- Do not render unsafe raw Pagefind `content` as HTML. Use safe excerpt/plain excerpt fields or escaped text.

### Typed Related Links

- Related links must render as typed sections on chapter and formal-object pages.
- Each relation row/card must show: readable relation label, target title, target family/type, one-line rationale or context, and a direct link.
- Relation categories must include conceptual, source/provenance, and learning-path relationships, but visible labels should be reader-friendly: `builds on`, `contrasts with`, `cited by`, `next readings`, or validated equivalents.
- Source/provenance relations must not obscure or replace the existing source trail UI; source trail remains the canonical provenance affordance.
- Empty related-link sections should use the empty copy above only where a section is expected but no relations exist; avoid rendering noisy empty panels on every page if the surface is not useful.

### Graph-Style Context

- Provide both a high-level global overview and local neighborhoods.
- Graph views must be static generated HTML/SVG/pages or JSON artifacts; do not introduce a runtime graph database or heavyweight graph engine.
- Local graph neighborhoods must emphasize path discovery: nearby next readings, route branches, typed relationships, and source/provenance context.
- Global overview must remain high-level. Do not render every formal object, concept, citation, and edge in one dense hairball.
- Every clickable graph node must be an actual link or keyboard-focusable control with visible focus and a 44px minimum target.
- Static SVG diagrams must have a text/list fallback or adjacent semantic list that contains the same clickable destinations.

| Surface | Required Components/Patterns | Contract |
|---------|------------------------------|----------|
| Discovery landing/search page | `SearchPanel`-style Astro component using Pagefind API plus existing atlas card styling | Use grouped result sections, local status messages, and direct anchor links; page max width 1080–1180px and page padding `3xl lg` desktop / `xl md` mobile |

| Graph overview | Static page under graph/discovery route | Use high-level owners/path nodes first; optional SVG connectors plus semantic list fallback |
| Local graph neighborhood | `GraphNeighborhood`-style Astro component/page | Show current node, typed outgoing/incoming relations, path memberships, and direct next-hop links |
| Generated JSON/index affordances | Existing local index output pattern | If exposed as pages/endpoints, include human-readable links to source pages where appropriate; keep machine JSON out of primary reading flow |

## Accessibility Contract

- Preserve semantic headings in order; every route map, search results group, related-link section, and graph neighborhood needs an accessible heading.
- Use `nav` only for true navigation groups such as route maps and graph node link lists; use `section` for search groups and related-link panels.
- All interactive controls require visible focus using existing `outline: 2px solid var(--atlas-color-accent); outline-offset: 2px` pattern.
- Every search filter, graph node, route stop link, and related-link target must be keyboard reachable.
- Color cannot be the only indicator for relation type, source status, branch membership, or search result type; include text labels.
- Decorative SVG connectors must be `aria-hidden="true"` and `focusable="false"`; meaningful SVG must have text alternatives or adjacent semantic lists.
- Narrow screens at `max-width: 720px` must collapse multi-column metadata, maps, and graph surfaces to one column with unchanged content order.
