# Phase 05 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Astro/Starlight components with existing local `.astro` component system; no shadcn/Radix/Base UI |
| Icon library | none; use text labels, badges, anchors, and existing atlas line/route treatments rather than adding icons |
| Font | Existing atlas sans stack: `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`; mono stack only for paths, anchors, source IDs, and code-like diagnostics |

Design-system source: existing `site/src/styles/atlas.css` tokens and Astro/Starlight static pages. No `components.json`, Tailwind config, shadcn preset, or third-party registry was detected in the repository or `site/` workspace. Because the active frontend stack is Astro/Starlight rather than React/Next/Vite, the shadcn initialization gate is not applicable for Phase 05.

Phase 05 must extend the current scholarly-atlas identity instead of introducing a second design language. The release-readiness page, coverage matrix, validation summaries, print treatment, and static output diagnostics must use existing source-grounded page patterns: warm paper background, compact bordered cards, visible source trails, semantic headings, visible focus states, and readable formal/math content.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps if any, inline badge gaps, compact metadata rows |
| sm | 8px | Compact element spacing, table-cell internal gaps, grouped diagnostic subitems |
| md | 16px | Default element spacing, card content gaps, form/control spacing |
| lg | 24px | Section padding, coverage-card padding, release-summary group spacing |
| xl | 32px | Layout gaps between major page regions and coverage drilldown groups |
| 2xl | 48px | Major section breaks between summary, matrix, diagnostics, and clean-checkout proof |
| 3xl | 64px | Page-level top/bottom spacing on release-readiness surfaces |

Exceptions: Interactive text links, buttons, summary rows, disclosure controls, and printable report actions must maintain a minimum 44px target height on screen. Dense coverage grid cells may use `sm` internal padding only when the row itself remains keyboard reachable and readable. Print CSS may reduce vertical spacing to preserve page flow, but must keep section separation at no less than 12px and must not collapse formal blocks, equations, source trails, or citation lists into unreadable clusters.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.15 |

Typography source: existing `--atlas-font-size-body`, `--atlas-font-size-label`, `--atlas-font-size-heading`, and `--atlas-font-size-display` tokens in `site/src/styles/atlas.css`, plus Phase 02 decision D-11 that the site is sans-interface-forward.

Additional typography contracts for Phase 05:

- Release diagnostics must use 16px body copy for reasons and next steps; do not shrink actionable failure text below 16px.
- Coverage matrix owner names, gate labels, source-tier labels, and pass/fail badges use 14px semibold labels.
- Path, anchor, source ID, citation key, and command text use the existing mono stack at 14px or 16px according to surrounding density; wrap long paths with `overflow-wrap: anywhere`.
- Print output must preserve academic reading hierarchy: page title at display size or print-scaled equivalent, section headings visually distinct, formal blocks and equations at body scale, and citation/source details legible without hover or scripts.
- Use only two weights in new Phase 05 UI: regular 400 and semibold 600. Do not introduce bold 700 or light weights.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F3EA` | Background, printed paper surface, default page canvas, quiet report regions |
| Secondary (30%) | `#E8DDC8` | Cards, coverage matrix containers, release summary panels, sidebar/nav surfaces, grouped diagnostic blocks |
| Accent (10%) | `#7A3E1D` | Primary CTA, current/selected coverage focus, pass/fail summary outline, links, focus outlines, section eyebrows, matrix drilldown affordances |
| Destructive | `#B42318` | Destructive actions only; also permitted for failed gate labels, broken-link diagnostics, missing-source diagnostics, blocked release status, and validation error counts |

Accent reserved for: primary release-readiness CTA, textual links, visible focus outlines, active/current navigation state, compact section eyebrows, semantic source/path affordances, coverage drilldown controls, and high-level release status emphasis. Accent must not be applied to every table cell, decorative background, or non-actionable paragraph.

Semantic status colors already present in `atlas.css` may continue to be used: `#166534` for success/pass states and `#475569` for muted/provenance-only/neutral metadata. Destructive red is for failure, blocking release state, missing canonical support, archive-blocked source paths, and confirmation text for any cleanup operation; it is not a general accent.

Print color contract: print pages must remain usable in grayscale. Status badges and coverage cells must include text labels such as `Pass`, `Fail`, `Thin support`, `Not supported`, or `Missing`; never rely on color alone.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Run Release Check |
| Empty state heading | No release diagnostics yet |
| Empty state body | Run the release-readiness command to generate coverage evidence, validation results, print checks, and deployable output diagnostics. |
| Error state | Release readiness failed. Review the grouped diagnostics below; each item lists the affected path or anchor, the reason, and the next step before publishing. |
| Destructive confirmation | Remove generated release artifacts: Confirm that only generated `site/dist` release artifacts and local indexes will be removed, then rebuild from source. |

Additional required copy patterns:

- Final success summary: `Release readiness passed. Static output, coverage evidence, source trails, citations, graph targets, math fixtures, accessibility checks, and print readiness are publishable.`
- Final blocked summary: `Release readiness blocked. Fix the failing gates below before publishing.`
- Coverage report empty owner state: `No coverage record was generated for this corpus owner. Check the coverage matrix generator and registry inputs.`
- Thin canonical support label: `Thin source support — release allowed only with the recorded source-grounded limitation.`
- Not-supported label: `Not supported by canonical source — do not present as a full derivation.`
- Print affordance label: `Print research handout`.
- Diagnostic row shape: `{Gate}: {Item} failed at {path or anchor}. Reason: {reason}. Next step: {nextStep}.`
- Clean-checkout proof label: `Clean-checkout proof`.
- Deployable output proof label: `Deployable static output`.

Copywriting source: Phase 05 context D-02 requires a unified pass/fail summary plus grouped actionable details with failing item, path/anchor, reason, and next step. Phase 05 context D-07 requires honest labels for thin or unsupported derivations/formal claims.

## Phase 05 Surface Contracts

### Release-readiness summary

- Render one top summary panel before details.
- Summary states: `Not run`, `Running` if represented during local development, `Passed`, `Blocked`.
- `Passed` state uses success green plus text label; `Blocked` state uses destructive red plus text label.
- The summary must show counts by gate group: provenance/source trails, citations, graph targets, math fixtures, coverage, accessibility/semantics, print readiness, clean-checkout/output shape.
- The first action is `Run Release Check`; secondary actions may be `Review Coverage Matrix`, `Print research handout`, and `Open deployable output` when available.

### Grouped diagnostics

- Diagnostics are grouped by gate, not dumped as an undifferentiated log.
- Every diagnostic row must include gate, item ID or title, path or anchor where applicable, reason, and next step.
- Long paths and anchors wrap; they must never overflow the viewport or printed page.
- Failed rows use destructive color only for status text/border; the body remains high-contrast text on dominant/secondary paper tones.
- Diagnostics must be keyboard navigable as normal links/details sections; no hover-only disclosure.

### Coverage matrix/report

- Use a compact grid for umbrella plus all twelve pillars.
- Required columns: owner, chapter sections, formal objects, concepts, citations, source trails, derivation coverage/rationale, discovery/index presence, diagnostics.
- Each owner row links to the relevant chapter, formal anchors, source trails, and failing diagnostics.
- Drilldown details must be visible through native links or accessible disclosure controls; do not require client-side graph interaction.
- Weak support states must be explicitly labeled as `Thin source support` or `Not supported by canonical source` using text and source-grounded rationale.

### Print/citation-friendly styling

- Add print rules to the existing atlas CSS rather than a separate design system.
- Hide navigation chrome, sidebars, route-map controls, search inputs, and graph CTAs in print.
- Preserve page title/context, headings, formal blocks, equations, citations, source trails, URLs/anchors, coverage report rows, and release summary status.
- Expand link URLs in print with `a[href]::after` or an equivalent visible URL treatment, excluding same-page noise only when the destination remains clear.
- Printed source trails remain inline in compact form and include expanded source paths or URLs in a print footer, appendix, or per-section source block.
- Apply print styling across homepage, umbrella/pillar chapters, formal registry, glossary, reading paths, graph/context pages, and release-readiness/coverage report.

### Accessibility and interaction

- Preserve existing visible focus outline: 2px accent outline with 2px offset.
- All interactive controls and links must have accessible names that match or clarify visible labels.
- Status cannot rely on color alone; include textual state labels.
- Coverage grid and diagnostics must retain semantic headings and table/list structure appropriate to their content.
- Narrow screens must collapse coverage details into readable stacked groups using the same spacing scale; do not require horizontal scrolling for the primary path to next steps.
