<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Package manager -> clean checkout proof | Dependency install state affects release reproducibility. |
| Child process commands -> release result | Build/check/test/index command output becomes pass/fail evidence. |
| Focused validators -> final publication gate | Independent gate results, including accessibility semantics, are normalized into one release decision. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06-01 | Tampering | dependency install proof | mitigate | Use `bun install --frozen-lockfile` in `release:clean-proof`; do not modify dependency manifests or install new packages. |
| T-05-06-02 | Repudiation | child command failures | mitigate | Capture command name, exit code/message, stdout/stderr summary, and focused rerun next step in diagnostics. |
| T-05-06-03 | Tampering | gate ordering | mitigate | Run Astro build and Pagefind/local indexes before coverage generation; then run accessibility, print, and output-shape validators against final generated output. |
| T-05-06-04 | Denial of Service | final release command | accept | Full release intentionally runs check/test/build/index once; no loops, network calls, or unbounded source scans are added. |
| T-05-06-SC | Tampering | npm installs | mitigate | No new packages; `release:clean-proof` uses existing `bun.lock` with frozen lockfile. |
</threat_model>
