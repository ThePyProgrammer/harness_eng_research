## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline metadata separators, source-trail row gaps |
| sm | 8px | Compact element spacing, badge padding, constellation label gaps |
| md | 16px | Default element spacing, paragraph-to-control spacing, formal-block internal rhythm |
| lg | 24px | Section padding, card padding, notebook derivation cell padding |
| xl | 32px | Layout gaps, sidebar-to-content breathing room, source panel spacing |
| 2xl | 48px | Major section breaks, homepage essay breaks, formal fixture groups |
| 3xl | 64px | Page-level top/bottom spacing on desktop, hero constellation margin |

Exceptions: minimum interactive target size is 44px by 44px for constellation links, sidebar links, footer previous/next links, source badges, and source/PDF/bibliography actions. Math cells may use horizontal overflow instead of compressing content below readable size. Starlight built-in chrome may retain its internal spacing where overriding it would reduce accessibility or maintainability.

## Typography

Declare exactly four text sizes and exactly two font weights for project-owned Phase 2 UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.15 |

**Typography rules:**

- Use the sans stack for homepage prose, navigation, source-detail pages, formal block prose, citations, bibliography summaries, and UI labels.
- Use the monospace stack only for repository paths, stable IDs, code-like cells, TeX snippets, and formal metadata rows.
- KaTeX output keeps the KaTeX fonts from `katex/dist/katex.min.css`; do not force the sans stack onto KaTeX math glyphs.
- Dense theorem, definition, citation, bibliography, and footnote content uses Body size 16px, weight 400, line-height 1.5.
- Labels, badges, metadata keys, source-status chips, block type labels, and navigation eyebrows use Label size 14px, weight 600, line-height 1.4.
- Decorative atlas labels must not drop below 14px.
- On narrow screens, preserve text size; reflow layout instead of shrinking labels or prose.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F3EA` | Page background, reading surface, Starlight content background, formal prose background |
| Secondary (30%) | `#E8DDC8` | Cards, sidebar/nav surfaces, source panels, formal block headers, notebook derivation cells |
| Accent (10%) | `#7A3E1D` | Corpus constellation anchor, active spine item, focus outlines, canonical source links, formal block left rule, primary CTA |
| Destructive | `#B42318` | Missing source, archive-blocked warnings, validation-failure states only |

Accent reserved for: primary CTA, active/current navigation marker, visible `:focus-visible` outline, canonical source/PDF/bibliography links, constellation central umbrella node and selected pillar node, formal-block type marker, source-trail canonical marker, and inline anchors. Do not use accent as a generic decoration wash or for all body text.

**Additional semantic colors:**

- Text: `#1F2933` for primary copy.
- Muted text: `#475569` for metadata, captions, secondary descriptions, and provenance-only status.
- Success/canonical: `#166534` for canonical status when a separate semantic cue is needed.

**Contrast and decoration rules:**

- All text must meet WCAG AA contrast against its immediate background.
- Non-text focus rings, constellation node outlines, badge borders, and source-status indicators must maintain at least 3:1 contrast.
- Cartographic textures, grid lines, and constellation edges must be decorative and low-emphasis; they must never carry the only state cue.
- Source status must use text labels plus border/color treatment, not color alone.

## Phase 2 Visual Contract

### Identity

- Use a rich scholarly-atlas direction: map-like, source-grounded, academic, original, and distinct from any research-lab clone.
- Homepage must lead with a visual corpus map/constellation before long explanatory prose.
- The umbrella framework visually anchors the twelve pillars.
- Atlas motifs may include static constellation lines, coordinate ticks, subtle map grid textures, source cards, and route-like spine indicators.
- Decorative effects must be static by default. If any transition is used, it must be nonessential, short, and disabled under `prefers-reduced-motion: reduce`.

### Layout

- Desktop reading shell uses Starlight sidebar as the primary navigation surface.
- Main prose column target width: 720px to 820px for long reading.
- Source-detail and formal fixture pages may use wider containers up to 1120px only when panels or notebook derivation cells require it.
- Narrow screens reflow into a single column; no page-level horizontal scrolling is allowed.
- Math and code-like cells may scroll horizontally within their own container.

### Surface Treatment

- Cards and formal blocks use Secondary background with a 1px border derived from Accent at low opacity.
- Formal blocks use a visible type marker and metadata row at the top; provenance/source trail remains visible by default.
- Notebook derivations alternate explanatory prose cells and math/code-like cells, each separated by md/lg spacing.
- Source panels are structured as definition-list rows for kind, slug, canonical `.tex`, PDF, bibliography, and source status.

## Interaction Contract

### Homepage Corpus Map

- Each constellation node is a real link with accessible text, not a hover-only hotspot.
- Umbrella node routes to `/corpus/umbrella/`.
- Pillar nodes route to `/corpus/{slug}/` source-detail pages in Phase 2.
- Keyboard focus order follows the same conceptual-arc order used by the book spine.
- Hover/focus state may emphasize node outline and connecting line, but the text label must remain visible without hover.

### Book Spine Navigation

- Use one shared conceptual-arc spine for homepage ordering, Starlight sidebar, source-detail page generation, and footer previous/next links.
- Required order for Phase 2 unless planner documents a stronger source-grounded rationale:
  1. Overview
  2. Umbrella framework
  3. Abstraction
  4. Information
  5. Reliability
  6. Coordination
  7. Temporal
  8. Economics
  9. Model Routing
  10. Human Interaction
  11. Quality
  12. Security
  13. Governance
  14. Accretion
- Sidebar is primary navigation. Footer previous/next navigation is subtle and secondary.
- Current page state must be visible through text/position plus accent marker, not color alone.

### Source-Detail Pages

- Every umbrella/pillar page includes summary, source status, canonical `.tex` link, canonical PDF link, bibliography link when present, and footer previous/next links.
- Source links must render from `corpusEntries`; do not duplicate canonical paths in page-local copy.
- Source-detail pages are lightweight Phase 2 pages, not full curated Phase 3 chapters.

### Formal Reading Components

Each reusable formal component must expose, visibly by default:

- block type/label,
- stable ID or label,
- owning pillar/page context,
- canonical source link,
- detailed source trail.

Required components for fixtures:

- `DefinitionBlock` for anchorable definitions.
- `TheoremBlock` or equivalent theorem-like `ClaimBlock` for theorems, propositions, lemmas, assumptions, and claims.
- `DerivationWalkthrough` for notebook-style alternating prose and math/code-like cells.
- `CitationRef` for readable academic citation references.
- `SourceTrail` for visible provenance details.

## Accessibility Contract

- Use semantic headings in order; no heading level jumps for visual styling.
- Provide a keyboard-visible focus state on every interactive element using a 2px Accent outline with at least 2px offset.
- Do not remove Starlight skip/bypass behavior.
- All links must have visible labels; URL/path-only links need surrounding labels such as `Canonical .tex source`.
- Formal blocks and source panels must be navigable by keyboard and understandable by screen readers as sections/articles with labelled headings.
- Source status must not rely on color alone; include the exact status label text.
- At 320 CSS px viewport width, content must reflow without page-level horizontal scrolling except contained math/code overflow regions.
- Text spacing changes must not break layout when users increase line height, paragraph spacing, word spacing, or letter spacing.
- Use `aria-label` or labelled headings for constellation/map navigation regions.
