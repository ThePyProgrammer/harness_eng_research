## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, formal metadata row micro-gaps, math-scroll padding |
| sm | 8px | Compact element spacing, badge padding, citation chips, list item gaps |
| md | 16px | Default element spacing, formal block metadata grids, card body gaps |
| lg | 24px | Section padding, formal block padding, concept card padding, source trail panel padding |
| xl | 32px | Layout gaps between chapter sections, registry result groups, derivation notebook groups |
| 2xl | 48px | Major section breaks between chapter contract sections |
| 3xl | 64px | Page-level top/bottom spacing for chapter, glossary, and registry index pages |

Exceptions: minimum interactive target is 44px for anchor links, source links, chapter navigation links, registry row links, concept card links, and copy-anchor controls. Horizontal math and code cells may overflow with `overflow-x: auto`; do not compress equations below legibility to preserve the spacing scale.

## Typography

Use exactly these four type sizes and two weights. Do not introduce additional visual sizes for Phase 3 formal content.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.15 |

Typography contract:
- Chapter prose uses Body size/400/1.5.
- Section headings, formal block titles, concept card titles, and registry group headings use Heading size/600/1.2.
- Page titles use Display size/600/1.15.
- Eyebrows, source tier labels, object kind labels, anchor IDs, owner labels, and registry facets use Label size/600/1.4.
- Formal IDs, source paths, notation snippets, BibTeX keys, and code-like derivation cells use the existing monospace family at Body or Label size only.
- KaTeX-rendered math must remain horizontally scrollable on narrow screens rather than scaled down into unreadable text.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F3EA` | Page background, chapter reading surface, derivation math cells, empty-state panels |
| Secondary (30%) | `#E8DDC8` | Cards, sidebar, nav, source panels, formal blocks, concept cards, registry rows |
| Accent (10%) | `#7A3E1D` | Stable anchor affordances, primary CTA, active book-spine marker, formal block left border, source links, object kind labels, focused states |
| Destructive | `#B42318` | Destructive or blocking validation states only: missing source, archive-blocked canonical source, broken registry link, duplicate formal ID diagnostics |

Accent reserved for: primary CTA, visible focus outline, formal block left border, current sidebar marker, stable ID/anchor affordance, source/citation links, source tier emphasis for supporting material, theorem/definition kind labels, and registry/glossary active-current links. Accent is not a generic decoration color and must not be applied to every paragraph, every card border, or non-clickable prose emphasis.

Additional semantic colors already present in the existing system:
- Text: `#1F2933` for primary content.
- Muted: `#475569` for secondary metadata, synthesis/review tier labels, and explanatory helper copy.
- Success: `#166534` for canonical source status and verified source trails.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Browse formal registry |
| Empty state heading | No formal objects registered yet |
| Empty state body | This chapter has a source trail, but its definitions, claims, citations, and concepts have not been curated into the registry yet. Add registry entries before marking the chapter complete. |
| Error state | Formal registry validation failed. Fix duplicate IDs, missing source paths, invalid owners, broken anchors, or Phase 3 relation targets, then run the site validation again. |
| Destructive confirmation | none — Phase 3 has no user-facing destructive actions |

Copy rules:
- Chapter headings use academic explainer language, not marketing copy.
- Formal blocks label kind first: `Definition`, `Assumption`, `Theorem`, `Proposition`, `Lemma`, `Corollary`, `Equation`, `Derivation`, or `Citation`.
- Every formal block exposes stable ID copy in the pattern `Stable ID: owner.semantic-name`.
- Source tier labels are exact and consistent: `Canonical`, `Supporting research`, `Synthesis/review`, `Archived provenance`.
- Unsupported or thin canonical sections say: `Supported by non-canonical context` and link the relevant supporting source trail.
- Avoid claims like “proves” unless the source trail contains proof or derivation support; otherwise use “states”, “frames”, “motivates”, or “interprets”.

## Phase 3 Component Contracts

### Curated Chapter Page

| Region | Contract |
|--------|----------|
| Header | Display chapter type eyebrow, page title, concise academic summary, owner/pillar metadata, and canonical source tier. |
| Sidebar | Preserve Phase 2 book-spine sidebar and current-page marker; do not replace with registry navigation. |
| Required sections | Render, in order: problem, core model, key notation, definitions, formal claims, derivation/proof context, interpretation, related pillars, citations, source trail. |
| Section source trail | Every major section shows visible source links and source tier labels by default. No provenance hidden behind an expand-only control. |
| Footer | Preserve previous/next footer navigation from the book spine. |

Interaction contract:
- A reader can deep-link directly to each formal object through its stable semantic ID.
- Anchor targets must scroll with enough top offset that the formal block title is visible below sticky navigation.
- Copy-anchor controls, if implemented, use the label `Copy stable link` and meet the 44px target minimum.
- Related pillar links stay static and reciprocal where Phase 3 owns both endpoints; graph visualization is deferred.

### Formal Blocks

| Block Type | Visual Contract | Required Metadata |
|------------|-----------------|-------------------|
| Definition | Secondary card, accent left border, `Definition` label, stable ID visible above body | stable ID, owner, source tier, source link |
| Theorem-like claim | Same formal block shell; label must match kind: theorem, proposition, lemma, assumption, corollary, or claim | stable ID, owner, source tier, source link, related concepts when present |
| Equation/derivation | Notebook-style treatment with prose cells and horizontally scrollable math/code cells | stable ID when registry-owned, owner, source trail, derivation context |
| Citation | Compact academic citation card with BibTeX key in monospace and readable title/author/year fields when curated | citation key, owner, bibliography/source path |
| Source trail | Visible metadata grid, source tier badge, canonical/supporting/provenance links | material kind, source status, path, PDF/source/bibliography links when available |

### Glossary / Concept Index

| Element | Contract |
|---------|----------|
| Concept card | Secondary card with term as Heading, aliases/notation as Label metadata, concise definition as Body text. |
| Aliases | Render as comma-separated metadata; each alias points back to the canonical concept entry if separately referenced. |
| Owning pillars | Render as static links to curated chapters. |
| Related formal objects | Render as stable-ID links grouped by kind. |
| Related concepts | Render as simple static reciprocal links only; no graph canvas or interactive traversal in Phase 3. |

### Formal Object Registry

| Element | Contract |
|---------|----------|
| Registry index | Group entries by owner and kind; each row links to the rendered block anchor. |
| Registry row | Show kind, label, stable ID, owner, source tier, and source status without requiring hover. |
| Broken/invalid entries | Never render as successful content. Validation failure copy uses the Error state above. |
| Empty owner group | Use the Empty state copy above and keep the group visibly incomplete for implementation review. |

## Accessibility and Narrow-Screen Contract

- Preserve visible `:focus-visible` outline: 2px solid `#7A3E1D`, 2px offset.
- All links and controls in chapter, glossary, registry, source trail, and formal block regions must have at least 44px interactive height or equivalent touch target spacing.
- Formal block metadata grids collapse to one column at `max-width: 720px`.
- Source paths, stable IDs, and BibTeX keys use `overflow-wrap: anywhere`.
- Math/code derivation cells use horizontal scrolling, not clipped overflow.
- Do not use color alone to distinguish source tiers; tier text labels must be visible.
- Heading hierarchy must remain semantic: one page `h1`; required chapter sections use `h2`; formal object titles inside sections use `h3` or component-equivalent accessible headings.

---

## Source and Provenance Interaction Contract

- Canonical sources link to `science/paper/` or `pillars/*/paper/` paths and associated PDFs/bibliographies.
- Supporting sources link to `science/synthesis/`, `science/reviews/`, `pillars/*/notes/`, `pillars/*/research/`, or `pillars/*/reviews/` and must be labeled `Supporting research` or `Synthesis/review`.
- Archive/provenance material must never appear as canonical; if rendered at all, label it `Archived provenance` and use destructive color only for blocked/invalid canonical usage.
- Every formal block and every major chapter section has visible source provenance by default.
- Registry IDs are semantic and stable, for example `reliability.compound-error-bound`; do not use paper theorem numbers or source line numbers as primary anchors.
